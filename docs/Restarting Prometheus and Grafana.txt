cd /fs/untd-1/threatos-monitoring

# sanity check the binaries actually exist here
ls -la prometheus/prometheus grafana/bin/grafana

If that ls shows the files, proceed:


pkill -f "prometheus --config" 2>/dev/null
pkill -f "grafana server" 2>/dev/null
sleep 2

nohup ./prometheus/prometheus \
  --config.file=prometheus/prometheus.yml \
  --storage.tsdb.path=prometheus/data \
  --web.listen-address=0.0.0.0:9090 \
  > /fs/untd-1/threatos-monitoring/prometheus.log 2>&1 &
echo "Prometheus PID: $!"

nohup ./grafana/bin/grafana server \
  --homepath ./grafana \
  --config ./grafana/conf/defaults.ini \
  > /fs/untd-1/threatos-monitoring/grafana.log 2>&1 &
echo "Grafana PID: $!"

sleep 5
curl -s http://localhost:9090/-/ready && echo " — Prometheus ready"
curl -s http://localhost:3000/api/health

If the ls -la above comes back empty or "No such file or directory," then the install actually lives somewhere else (or under a different name) and we need to locate it first — run:


find /fs/untd-1 -maxdepth 3 -iname "prometheus" -o -iname "grafana" 2>/dev/null

and paste the output so I can give you the correct paths.

Tip to avoid this in future: since nohup ... & runs in the background instantly, the shell doesn't wait to tell you if the command itself failed to even start — that's why you got a PID printed (868671) but then saw Exit 127 a moment later. Exit code 127 = "command not found," which is the giveaway it's a path issue, not a crash.
